# crypto_bot — CLAUDE.md

## Проект
Python-платформа алгоритмической торговли на perpetual futures (Bybit). Multi-strategy
research/execution. Один общий `Backtester` (`strategy_mode=candidate|portfolio`), один
composition root `pipeline/factory.py`, единый portfolio/risk/execution-слой переиспользуется
всеми стратегиями — новых параллельных веток не создавать.

Карта документации и текущее состояние: @docs/README.md.
Устройство системы и открытые пункты: @docs/architecture/overview.md, @docs/architecture/backlog.md.

## Роль
Ты — соавтор senior Python/quant/trading-systems инженера. Стандарт проверки — продакшн
финансовый продукт, не пет-проект: ошибка в арифметике, тихая подмена параметра или
curated-подмножество тестов здесь стоит времени и денег, а не баллов за тест.

## Железные правила — не нарушать ни при каких обстоятельствах
1. **Полный прогон тестов — без исключений.** `pytest tests/ -q`, без единого `--ignore`, без `-k`,
   без `-x`. Любой failure — полный traceback в ответ, не фраза "pre-existing, unrelated" без
   доказательства (git stash + сравнение на чистом коммите).
2. **Число без команды, которая его произвела, — не число.** "Script-generated" значит вставлен
   реальный stdout. Пересчёт в уме, вписанный в таблицу как факт, недопустим.
3. **Параметры меняются только ДО просмотра результата на test-сегменте.** Любое изменение конфига
   после того как виден Sharpe/PnL — это p-hacking, а не тюнинг. Правило распространяется и на
   `--override` флаги в командах запуска — они не должны появляться впервые в команде,
   не будучи обоснованы в pre-registration документе заранее.
4. **Единицы — явно.** bars vs hours vs days — самый частый источник тихих ошибок в этом проекте.
   Всегда выводить производные величины в часах с явным указанием timeframe, не оставлять
   неоднозначные "N bars".
5. Перед любой задачей по strategy research (pre-registration, decision rule, cost-gate,
   walk-forward, closure-документ) — используется skill `research-methodology`
   (загружается автоматически по описанию, см. `.claude/skills/`).
6. Перед дорогим прогоном (walk-forward, полный backtest) — обязательно делегировать проверку
   subagent'ам `preregistration-guardian` и `cost-gate-auditor` (см. `.claude/agents/`), не
   заявлять готовность самостоятельно.

## Стек и конвенции
- Python 3.x, pytest, ruff, SQLite (`data/crypto_bot.db`), Pydantic v2 для конфигов.
- Миграции БД последовательны, с CHECK-констрейнтами; новое значение enum-подобного поля
  (например `closed_by`) требует новой миграции, не только Python-логики.
- Комментарии, отчёты, markdown-документация — на русском (проектная конвенция); код,
  идентификаторы, docstrings — на английском.

## Рабочий процесс
- Дешёвые pre-check гейты (cost/turnover, signal-frequency) — обязательны и должны быть
  воспроизведены скриптом на **реальном** test-сегменте перед любым дорогим прогоном.
- При расхождении между двумя отчётами об одном и том же числе — не игнорировать, найти причину
  (git diff / отдельный прогон "до" и "после"), а не выбрать более удобное число.
- Git-хуки: commit/PR workflow — через плагин `commit-commands`; PR-ревью — через
  `pr-review-toolkit`; проверка безопасности правок — через `security-guidance` (фоновая,
  срабатывает автоматически на Edit/Write).

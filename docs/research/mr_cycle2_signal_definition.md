## 1. Решение

Для каждого символа в момент решения `t` (закрытие последнего закрытого бара, timeframe 1h):

```
r_1(j) = ln(close_j / close_{j-1})                                однобарная лог-доходность
r_h(t) = ln(close_t / close_{t-h}) = r_1(t-h+1) + ... + r_1(t)       h = 4 бара = 4 ч
s_1(t) = sqrt( (1/W) * sum_{j = t-h-W+1 .. t-h} r_1(j)^2 )           W = 168 баров = 168 ч = 7 сут
s_h(t) = sqrt(h) * s_1(t)
z(t)   = r_h(t) / s_h(t)
```

Четыре свойства, каждое — отдельное решение (раздел 2):

1. **Горизонт согласован:** числитель и знаменатель — величины горизонта `h`; `s_h` оценивает
   стандартное отклонение `h`-часовой доходности.
2. **Оценка по однобарным доходностям** с масштабом `sqrt(h)`, а не по `h`-часовым.
3. **Окно оценки не пересекается с окном сигнала:** последний бар окна — `t-h`.
4. **Нулевое среднее**, логарифмические доходности.

Минимальная история: `W + h + 1 = 173` закрытых бара. Жёсткий потолок — 400 баров: столько
отдаёт `HistoricalCandleSource.slice` (`limit=400`, `simulation/historical_source.py:62`), и
столько же задаёт `timeframes.candles_per_tf`. Окно с `W + h + 1 > 400` не упало бы с ошибкой —
символ молча выпадал бы из снапшота на каждом тике, и сигналов не было бы вовсе.

## 2. Обоснование

### 2.1 Согласование горизонта — обязательное условие, не выбор

Дефект, закрывший v1–v4: 8-часовая доходность делилась на std часовых. На синтетическом
гауссовом нуле определение «как в коде v1–v4» даёт `std(z) = 2.779` и `P(|z|>=2) = 47.373%`,
то есть 10.41x нормального (приложение A, раздел 3). Согласование горизонта устраняет
именно это.

### 2.2 Оценка `s_h`: однобарные доходности с масштабом `sqrt(h)`

Стандартное отклонение `h`-часовой доходности по окну `W` баров можно оценить тремя способами.
Гауссов iid, `h = 4`, `W = 168` (приложение A, разделы 2–3):

| способ | эффективный размер выборки | `P(\|z\|>=2)`, МК гаусс |
|---|---:|---:|
| перекрывающиеся 4ч-доходности | `N*3h/(2h^2+1)` = 61.1 | 4.957% |
| непересекающиеся 4ч-доходности | `N/h` = 42.0 | 5.184% |
| **однобарные с масштабом `sqrt(h)`** | **`N` = 168** | **4.662%** |

При одном и том же окне однобарная оценка использует всю информацию окна, перекрывающиеся
`h`-доходности — её часть, непересекающиеся — ещё меньше.

**Цена выбора — явная.** Оценка опирается на масштабирование случайного блуждания
`Var(r_h) = h * Var(r_1)`. Если часовые доходности автокоррелированы, `s_h` смещена в
`sqrt(VR(h))` раз. Это не допущение, принимаемое на веру, а проверяемое утверждение: гейт G1
(раздел 6.1) меряет `std(r_4h)/std(r_1h)` по каждому символу — ровно проверку
`std(Nh)/std(1h) ≈ sqrt(N)` из handoff (раздел 4). Прежнее измерение того же отношения для
`h = 8` на train v4 — 2.8187 против `sqrt(8)` = 2.8284 (closure, раздел «Измерение»): довод
в пользу, но не замена гейта — окно и горизонт другие.

Формулировка handoff «std того же горизонта» выполнена: оценивается стандартное отклонение
`h`-часовой доходности. Меняется эстиматор, не величина.

### 2.3 Окно `W = 168` баров

Три довода, в порядке веса.

1. **Сезонность.** 168 ч — ровно неделя: каждый час недели входит в окно ровно один раз при
   любом положении `t`. Окно, не кратное 24 ч, в зависимости от часа решения по-разному
   представляет часы суток; не кратное 168 ч — дни недели. Оценка `s_1` становилась бы
   функцией фазы, а не только волатильности.
2. **Точность.** При гауссовом нуле `z ~ t_168` (числитель и знаменатель независимы, п. 2.5):
   `P(|T_168|>=2) = 4.711%` против нормальных 4.550% (приложение A, раздел 2). МК: 4.662%.
   Для сравнения: окно 48 баров v4 на перекрывающихся 8ч-доходностях — 10.19%, 2.24x
   (приложение A, раздел 1, воспроизводит таблицу handoff).
3. **Отзывчивость.** Удвоение окна почти ничего не даёт: `W = 336` — 4.571% против 4.662%
   (гаусс), 6.071% против 6.108% (GARCH). При GARCH избыток не уходит с ростом окна — он
   свойство процесса (кластеризация волатильности), а не шум оценки. Более длинное окно дало
   бы только большее запаздывание `s_1` за сменой режима волатильности.

Оговорка: при тяжёлых хвостах выборочная дисперсия шумнее, чем при гауссе, и эффективное
число степеней свободы меньше `W`. МК на Стьюденте `nu = 5`: 5.154% (`W = 168`) против
4.987% (`W = 336`). Реальную величину даёт гейт G3.

### 2.4 Нулевое среднее

План (Вариант A) говорит «относительно собственного rolling mean/std». От среднего
отказываемся сознательно:

- на горизонте 4 ч дрейф пренебрежим, а скользящее среднее `W` часовых доходностей — это
  прошлая недельная доходность, делённая на `W`: почти чистый шум, добавляющий дисперсию `z`.
  МК, гаусс: 4.942% с вычитанием среднего против 4.662% без него;
- по смыслу числитель `r_h - h*mean` превращается в контраст «4ч-доходность против недельного
  тренда» — сигнал с компонентой следования за трендом, которую гипотеза не заявляет.

### 2.5 Окно оценки не пересекается с окном сигнала

- При независимых доходностях числитель и знаменатель независимы, и `z ~ t_W` точно (гаусс):
  у гейта есть теоретическая частота, с которой сверять.
- Если окно включает текущие `h` баров, крупное текущее движение раздувает собственную `s`
  и маскирует само себя — ровно на тех событиях, ради которых существует стратегия. В МК это
  видно как недобор хвоста на нуле: 4.455% против 4.662% (гаусс).
- Цена — оценка старше на `h = 4` бара при окне 168. Пренебрежимо.

### 2.6 Логарифмические доходности

Аддитивность: `r_h` — ровно сумма `h` однобарных, и масштаб `sqrt(h)` при iid точен.
Попутно: нынешний `_returns_from_closes` в докстринге назван «log returns», а считает простые
доходности. Рассогласование устраняется.

## 3. Рассмотренные альтернативы

### 3.1 Непересекающиеся окна — отклонено

Эффективный размер `W/h = 42` — хуже обеих других оценок (МК: гаусс 5.184%, GARCH 6.491%),
плюс результат зависит от фазы сетки блоков. Доминируется.

### 3.2 «std того же горизонта» буквально: перекрывающиеся `h`-доходности — отклонено

При том же `W = 168`: эффективный размер 61.1 против 168, МК 4.957% против 4.662%. Даже
удвоенное окно (`W = 336`, 4.737%) хуже выбранного определения при вдвое меньшем
запаздывании последнего.

### 3.3 Более короткий горизонт (`h = 1` ч) — отклонено

- Каскад ликвидаций, развивающийся несколько часов, делится между свечами и может не дать
  экстремума ни в одной из них; окно должно вмещать движение целиком.
- При фиксированной стоимости round-trip отношение издержек к типичному движению растёт как
  `1/sqrt(h)`: при `h = 1` вдвое хуже, чем при `h = 4`.

### 3.4 Более длинный горизонт (`h = 8` ч) — отклонено

- При `h = 8` для того же `z` нужно движение в `sqrt(2)` раз больше: каскад длительностью
  1–3 часа тонет в фоне остальных часов окна.
- 8 ч совпадает с периодом фандинга, но фандинг — механизм Варианта C (отдельная гипотеза).
  Выбирать горизонт под него — смешивать гипотезы.
- 8 ч было горизонтом v4; это не довод ни за, ни против.

Почему именно 4, а не 2, 3, 5 или 6: окно должно вмещать движение каскада целиком (иначе
его часть уходит в соседнее окно), но не быть намного длиннее (иначе фон разбавляет
событие). Горизонт выбран по верхней границе типичной длительности каскада — «часы» из
экономического обоснования плана (раздел 1). Это экономическое допущение, а не измерение, и
оно фиксируется до данных именно поэтому.

### 3.5 MAD вместо σ — отклонено

Главный довод — не эффективность, а смысл метки. `1.4826 * MAD` оценивает σ только при
нормальности; при тяжёлых хвостах она оценивает **меньший** масштаб, чем стандартное
отклонение, `z` завышается, и «k σ» перестаёт означать k стандартных отклонений. МК:

| модель | `std(z)` | `P(\|z\|>=2)` | избыток |
|---|---:|---:|---:|
| гаусс | 1.012 | 4.846% | 1.07x |
| Стьюдент `nu = 5` | 1.208 | 9.174% | 2.02x |
| GARCH-t5 | 1.294 | 10.393% | 2.28x |

Это тот же класс дефекта, что закрыл v1–v4: метка сигмы не соответствует распределению.
Выгода робастности при `W = 168` мала: один выброс даёт вклад `1/168` в среднее квадратов.

### 3.6 Иная конструкция сигнала

- **Рыночно-нейтральный остаток** (`r_h` символа минус среднее по вселенной, затем
  стандартизация). Ближе к слову «cross-sectional», меньше кластеризация, книга ближе к
  net-zero. Отклонено для этого цикла: это другая гипотеза — она по построению вычитает
  рыночные каскады, крупнейший класс ликвидаций, — а план требует регистрировать иную
  конструкцию отдельной стратегией, не параметром внутри `mean_reversion_v0` (план,
  раздел 4). Цикл 2 проверяет гипотезу, которую v1–v4 заявляла, но ни разу не измерила
  (closure: «Экономическая гипотеза не тестировалась ни разу»). Естественный кандидат на
  следующий цикл при REJECT.
- **Отклонение цены от скользящего уровня (Bollinger).** «Возврат» к скользящему среднему
  случается и тогда, когда среднее догоняет цену, — та же проблема семантики выхода, что у
  выхода по `|z|` (п. 4.2), плюс ещё одно окно-параметр.
- **Funding-conditioned (Вариант C).** Требует funding-данных на validation/test, а их нет
  (план, раздел 0, п. 3: «Funding data только до Feb 2024»).
- **EWMA-волатильность.** При той же «памяти» эквивалентное число наблюдений меньше, и нет
  точного нулевого распределения (`t_W`) для сверки гейтом.
- **Поправка на внутрисуточную сезонность.** Делала бы `z` честнее по часам суток, но
  требует оценки по каждому часу (при 7 сутках — 7 наблюдений на час). Скан печатает частоту
  по часам суток как диагностику, без порога.

## 4. Решения, следующие из определения — фиксируются сейчас

Ни одно из них не зависит от измеряемой частоты. Они фиксируются до измерения, чтобы после
него свободным оставался только порог входа — и тот выбирается механически (п. 6.3).

### 4.1 Каденция `rebalance_hours = 1` — решение на каждом баре

- **Свежесть входа:** вход в первый час, когда 4-часовое движение пересекло порог, а не
  через `R-1` часов.
- **Нет непокрытого времени.** В v4 каденция 12 ч при горизонте 8 ч оставляла треть времени
  вне окон сигнала (v4, раздел «Снятый инвариант»).
- **Точный time-stop:** выход проверяется каждый час; механизм «60 ч вместо 48 ч» (раздел 8,
  п. 1) при каденции в один бар невозможен.
- Это исходная каденция Варианта A: «Ребалансировка: каждый бар (1h)» (план, раздел 4).

Следствие для измерения: соседние часовые `z` перекрываются (`h-1 = 3` общих бара), одно
событие даёт серию часов с `|z| >= k`. **Единица сырого события — «начало»:** час с
`|z| >= k`, которому предшествует час с `|z| < k`. МК, гаусс: доля часов с `|z|>=2` —
4.662%, доля начал — 2.937%.

### 4.2 Выход — только по времени, `M = h = 4` ч; выход по `|z|` исключён

Выход по `|z| <= exit_threshold` не измеряет возврат цены ни при каком `z`, построенном на
скользящей `h`-часовой доходности. Через `h` часов после входа `z` описывает только движение
за эти `h` часов — то есть собственный результат позиции:

- сильный возврат (прибыль) даёт большой `|z|` — правило **держит** завершившуюся реверсию;
- сильное продолжение (убыток) тоже даёт большой `|z|` — правило держит;
- правило срабатывает, когда последние `h` часов были **тихими**.

Closure фиксировал то же с другой стороны: «`|z| <= 0.5` наступает, когда 8-часовая
доходность перестаёт быть необычной, то есть когда движение прекращается, а не когда цена
возвращается».

Выход по времени проверяет гипотезу напрямую: «после необычного 4-часового движения
следующие 4 часа дают частичный возврат». `M = h` — симметричный горизонт без
дополнительного свободного параметра.

Конфигурация: `exit_threshold: null` (выход по `|z|` отключён явно, а не значением, которое
«почти никогда» не срабатывает: `|z| <= 0` при ценах с конечным шагом случается на
неподвижном рынке), `max_holding_bars: 4`, `min_expected_edge_bps: 0` — фильтр определён как
расстояние до уровня выхода по `|z|` и без него смысла не имеет; комбинация `null` + `> 0`
будет запрещена валидатором.

### 4.3 Исполнение: `market` / `market`

Skill: «decision rule должен применяться к pessimistic, если explicit fill-probability модель
ещё не реализована». Модели нет (v4, Open Items, п. 1). Что бэктестер реально начисляет:

| исполнение | модель издержек (`simulation/walk_forward.py:209–222`) | на сторону | round-trip |
|---|---|---:|---:|
| **market / market** | `bybit_perp_default()`: `SimpleFeeModel()` 0.1% maker и taker; проскальзывание 0, т.к. `spread_pct = 0.0` для market-стратегий (`simulation/backtester.py:603`) | 10 bps | **20 bps** |
| post_only / post_only | `bybit_perp_maker_only()`: 0.02% maker, исполнение при касании лимита = 100% | 2 bps | 4 bps |

Вторая строка — оптимистичная граница без модели заполнения, поэтому не используется.
Попутно исчезает сдвиг `opened_at` на бар исполнения post-only (раздел 8, п. 1).

### 4.4 Режимный гейтинг: нейтральный, все множители 1.0, явно

- Полезность режимного гейта не доказана (план, раздел 0, п. 2); совместный тест
  «MR + гейт» смешивает две гипотезы.
- Гейт срезает сделки на неизмеренную долю (closure: `trend_high_vol` — около 14% тиков train
  v4).
- Без override для стратегии fusion и так даёт 1.0 (`pipeline/portfolio_fusion.py`,
  `_get_multiplier`), но значения выписываются явно: отсутствие блока в снимке неотличимо от
  забытого.
- Режимно-условный MR — отдельная гипотеза, не этот цикл.

### 4.5 Веса: `equal`

Веса нормируются по выбранной на тике книге, а удерживаемые позиции не ресайзятся
(`PortfolioExecutor.open_position` возвращает «position already open»). Одиночная позиция
поэтому всегда получает 100% капитала, какой бы ни была её волатильность. `inverse_vol` в этой
системе не выравнивает риск на сделку, но добавляет второй, незарегистрированный оценщик
волатильности (`_inverse_vol_weights`: `lookback_bars=24`, простые доходности с вычитанием
среднего). `equal` скрытых параметров не имеет.

Известное следствие, фиксируемое явно: брутто-экспозиция зависит от пути. При четырёх
последовательных входах в разные тики — `1 + 1/2 + 1/3 + 1/4` капитала; маржинально
ограничено `max_leverage = 5.0`.

### 4.6 Отбор и ёмкость книги

- `long_percentile = 0.80`, `short_percentile = 0.20`: `ceil(0.2 * 8) = 2` кандидата на
  сторону за тик (по поправке 1 вселенная — 8 символов; при 9 было бы тоже 2). Это поперечный элемент Варианта A (ранжирование «топ/дно вселенной»): в
  кластере, когда порог пробивают многие символы разом, берутся самые экстремальные в
  единицах собственной σ.
- `portfolio.risk.max_positions = 4`: одна полная выборка тика (2 + 2) помещается в книгу
  целиком.
- `mean_reversion.max_positions = 4`: поле декоративно (раздел 8, п. 2); значение равно
  реальному ограничителю, чтобы не вводить в заблуждение.
- При переполнении книги инкумбенты всегда впереди новых кандидатов, новые упорядочены по
  `|z|` по убыванию независимо от стороны (исправление дефекта, раздел 7, п. 3).

Совпадение с v4 (0.80 / 0.20, 4) оговаривается: в v4 `max_positions` подняли с 2 до 4 ради
`n_trades >= 200` (v4, «Registered Parameter Grid»). Здесь основание другое — ёмкость одной
выборки тика.

### 4.7 Прочее

`timeframe: 1h`; `seed: 42` — ветка `mean_reversion_v0` в `pipeline/factory.py` поле не
передаёт, на поведение оно не влияет. `entry_threshold` выбирается на шаге 3 (п. 6.3).

## 6. Предобъявленные гейты

Всё в этом разделе зафиксировано до измерения. Любой провал останавливает цикл: регистрация
не пишется, провал документируется, и новое решение оформляется новым документом, где
прямо сказано, что оно принято после увиденной частоты. Значения этого документа по месту не
правятся.

### 6.1 Статистическая валидация фичи — только train

Считается реальной функцией признака на каждом символо-часе train-сегмента всех 8 символов
вселенной (адаптированный `scripts/scan_sigma_events.py`).

| гейт | что | граница PASS |
|---|---|---|
| **G1** | `std(r_4h) / std(r_1h)`, лог-доходности, весь train, **по каждому** символу | `[1.8, 2.2]` = `sqrt(4)` ± 10% |
| **G2** | `std(z)` по всем символо-часам train | `[0.90, 1.10]` |
| **G3** | `P(\|z\| >= 2)` по всем символо-часам train | `[3.41%, 6.83%]` = `[0.75, 1.50]` x 4.55% |

Границы G1 и G2 согласованы: отношение в `[1.8, 2.2]` — это `VR(4)` в `[0.81, 1.21]`, и
ровно в этих пределах `std(z)` выбранного определения остаётся в `[0.90, 1.10]`.

Почему такие границы: во всех трёх синтетических моделях они отделяют оба класса дефекта
прошлой линии от выбранного определения (приложение A, раздел 3):

| определение | `std(z)` | `P(\|z\|>=2)` | избыток | G2 / G3 |
|---|---:|---:|---:|---|
| v1–v4 код | 2.774–2.810 | 46.403–47.373% | 10.20–10.41x | FAIL / FAIL |
| скан v4 «верный» (малая выборка σ) | 1.159–1.181 | 8.441–8.982% | 1.86–1.97x | FAIL / FAIL |
| MAD, `W = 168` | 1.012–1.294 | 4.846–10.393% | 1.07–2.28x | FAIL при тяжёлых хвостах |
| **выбранное** | **1.006–1.058** | **4.662–6.108%** | **1.02–1.34x** | PASS / PASS |

Верхняя граница G3 (1.50x) сознательно выше 1.34x, которые выбранное определение даёт на
иллюстративном GARCH-t5: кластеризация волатильности и тяжёлые хвосты — свойства процесса,
удвоение окна их не убирает (6.071% при `W = 336`). И сознательно ниже 1.86x дефекта малой
выборки. Параметры GARCH не откалиброваны на данных проекта — это иллюстрация порядка
величины, а не прогноз.

Диагностика без порога: `P(|z|>=2.5)` и `P(|z|>=3)` против нормального и `t_168`;
`std(z)` и частота по каждому символу; частота `|z|>=2` по часу суток; те же статистики при
`W = 336` (чувствительность к окну).

**Попутное уточнение прошлого документа.** Closure писал об эвристике `n_eff = W/h`:
«точная эффективная степень свободы … ниже, то есть эффект скорее недооценён». Асимптотика
говорит обратное: для перекрывающихся сумм `n_eff = N*3h/(2h^2+1)` = 8.9 при `h = 8`,
`N = 48`, то есть больше эвристических 6 (приложение A, раздел 2). Главный вывод closure при
этом подтверждается независимо: на **гауссовом** синтетическом нуле «верный» `z` скана v4
даёт 8.441%, так что наблюдавшиеся на train v4 8.51% объясняются малой выборкой σ без толстых
хвостов. Сверка не тавтологична: синтетика не использует данных. Но только для train:
10.96% (вся история) и 11.42% (test v4) из того же closure выше и гауссова нуля (8.441%), и
GARCH-t5 (8.982%) — там есть и другие вклады.

### 6.2 Измерение частоты — сырые начала, не `n_trades`

По каждому сегменту (train, validation, test) и каждому `k` из `{2.0, 2.5, 3.0}`: число начал
(двусторонних, по всем символам), начал в сутки, число различных часов хотя бы с одним началом
(мера кластеризации). Средний `|r_4h|` в момент начала — только на train (он нужен cost-гейту).

Скан считает начала по каждому символу независимо, без селекционного капа, `max_positions` и
исключения удерживаемых позиций. Это верхняя граница, не оценка `n_trades`.

На test печатаются только счётчики. Измерение сырой частоты на test-сегменте — санкционированный
signal-frequency pre-check (skill: «Период проверки — реальный test-сегмент будущего
walk-forward split»); доходности после сигнала не считаются.

### 6.3 Правило выбора порога входа

```
K = {2.0, 2.5, 3.0}

n_train(k)  = PnLSummary.total_trades реального Backtester на train-сегменте;
              конфигурация — регистрируемая, кроме entry_threshold = k
              и risk.emergency_drawdown_pct = 100.0 (diagnostic_widened:
              стоп по просадке не должен цензурировать счёт).
              Скрипт печатает только счётчики — без PnL, эквити и Sharpe.
N_proj(k)   = n_train(k) * onsets_test(k) / onsets_train(k)

k* = max { k in K : N_proj(k) >= 300 }
```

Проверка идёт от 3.0 вниз и останавливается на первом успехе. Если ни одно `k` условию не
удовлетворяет — гейт мощности FAIL, регистрации нет.

Handoff (раздел 3) заканчивается фразой «Выбирать порог, уже видя частоту, — подгонка», а
задание цикла требует выбрать порог на основании измеренной частоты. Противоречие снимается
тем, что правило зафиксировано здесь, до измерения: частота в него только подставляется, а
выбор между порогами по виду чисел не делается.

**Почему наибольший подходящий `k`.** Гипотеза предсказывает более сильный возврат после
более сильной дислокации; фиксированная стоимость round-trip — меньшая доля большего движения;
меньше сделок — меньше суммарных издержек. Единственная причина идти ниже — мощность теста.

**Почему 300.** `300 = 1.5 * 200`: запас на то, что доля начал, доходящих до сделки, на test
может отличаться от train (иная кластеризация рынка). Порядок величины — документированная
вариация частоты между сегментами прошлой линии, 1.34x (closure, «Запас над порогом»).

**Осуществимость на гауссовом нуле** (приложение A, раздел 5, после поправки 1): ожидаемых
сырых начал на test 1675 (`k = 2.0`), 537 (`k = 2.5`), 128 (`k = 3.0`). На гауссе `k = 3.0` не
набирает 300 даже как верхняя граница; тяжёлые хвосты поднимают её (МК, GARCH: доля начал
0.771% против 0.224%). Решает измерение, а не эта оценка.

### 6.4 Cost-гейт — пессимистичный

Стоимость round-trip — 20 bps (п. 4.3). Три числа, все из скрипта
(`scripts/estimate_mr_turnover.py`, расширяется двумя необязательными флагами):

- **(а) Формула skill — граница ёмкости:** `max_positions * min(24/holding, 24/rebalance) =
  4 * min(24/4, 24/1)` round-trip в сутки. Она предполагает, что все 4 слота заняты
  непрерывно и оборачиваются каждые 4 ч. Для стратегии, входящей по порогу, эта граница не
  связывает, когда события реже ёмкости; ожидаемый FAIL скрипта в этой строке — не вердикт
  гейта. Печатается, потому что skill требует формулу с обоими ограничителями.
- **(б) Граница по сигналу:** round-trip в сутки не больше `min(ёмкость, N_proj(k*) / 297.00)`
  (длина test в сутках после поправки 1).
- **(в) Критерий PASS:** `rho_req = 20 bps / mean|r_4h|` в моменты начал на train при `k*`
  `<= 25%`. То есть для безубыточности должно в среднем возвращаться не больше четверти
  движения, на котором был вход.

Funding: данных нет после февраля 2024 (план, раздел 0, п. 3). PnL validation и test — до
фандинга; это раскрывается в регистрации.

### 6.5 Decision rule — предварительно (буквальная версия — в pre-registration)

Структура плана без изменений: Test Sharpe > 0 при production DD 25%, Validation Sharpe > 0,
`n_trades(test) >= 200`, знак Sharpe > 0 не менее чем в 2 из 3 под-окон. Что фиксируется
сейчас:

- **Под-окна** — три последовательных равных календарных части test-сегмента. Эквити
  test-прогона берётся из таблицы `equity` его БД (`--db-dir`), доходность между соседними
  тиками относится к под-окну более позднего тика, Sharpe считается той же формулой, что
  `PnLSummary`. Инструмент (`scripts/mr_subwindow_sharpe.py`) коммитится до прогона.
- **Единицы Sharpe.** `PnLSummary.sharpe_ratio` — среднее / std доходностей эквити **по
  тикам**, то есть часовых при 1h, умноженное на `sqrt(365)` — дневной множитель
  (`simulation/pnl.py`). Величина занижена против годового Sharpe примерно в `sqrt(24)` раз.
  Правило использует только знаки, поэтому вердикт не затронут, но величины несравнимы с
  годовым Sharpe и с числами других проектов.

## 8. Открытые пункты handoff — статус в этом цикле

1. **`time_stop` 60 ч вместо 48 ч.** Механизм найден чтением кода: для post-only входа
   `opened_at_ms` пишется временем **исполнения** (`process_post_only_entries`,
   `opened_at_ms=timestamp_ms` бара, на котором лимит исполнился), то есть не раньше, чем
   через бар после тика решения. При каденции 12 ч возраст на тике `T+48` — 47 баров < 48, и
   выход уезжает на `T+60 = 48 + 12`. Это согласуется с «18 из 18» и с лишним интервалом
   каденции, но прогоном в этом документе **не подтверждено**. При каденции в один бар и
   рыночном входе механизм невозможен: возраст на тике `T+4` ровно 4 бара. Общая починка
   (каденция > 1 бара вместе с post-only) — вне скоупа, отдельная задача.
2. **`mean_reversion.max_positions` декоративен** — не трогается; значение равно реальному
   ограничителю `portfolio.risk.max_positions`.
3. **`signal_frequency_check.py`** — в этом цикле не используется. Оценка `n_trades` —
   реальным `Backtester` на train (п. 6.3). Скрипт получает только переименование поля
   `ZScoreSnapshot`, чтобы оставаться импортируемым.
4. **Нет `check_positions` в живом оркестраторе** — вне скоупа (блокер paper-trading).
5. **AVAX** — механизм найден (поправка 1): у бэктестера нет спецификации AVAXUSDT, и вход по
   нему отвергается fail-closed. Символ исключён из вселенной цикла.

Найдено на этом шаге:

6. Единицы `sharpe_ratio` (п. 6.5).
7. `--max-leverage` и `--maintenance-margin-buffer` в `scripts/walk_forward.py` передаются в
   `_run_single_window`, но там не используются: `Backtester` строит риск-движок из

import json, datetime as d

for s in ['BTC', 'ETH', 'SOL', 'XRP', 'AVAX', 'ADA', 'DOGE', 'BNB', 'POL']:

"
